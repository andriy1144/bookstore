# Архітектура компонентів проєкту "BookStore"

Цей документ описує структуру клієнтського застосунку, розподіл відповідальності між компонентами та їхні контракти (згідно з ЛР 1.2).

## 1. Ієрархія компонентів
Дерево відображає вкладеність компонентів на поточному етапі розробки:

App (Точка входу, передає глобальні дані)
 └── AppLayout (Головна оболонка)
      ├── SiteHeader (Шапка)
      │    └── MainNav (Навігація)
      ├── HomePage (Сторінка каталогу)
      │    ├── Section (Обгортка секції "Каталог")
      │    └── BookList (Список книг)
      │         └── BookCard (Картка окремої книги)
      │              ├── AvailabilityBadge (Статус наявності)
      │              └── AppButton (Кнопки дій)
      └── OrderPage (Сторінка оформлення замовлення)
           ├── Section (Обгортка секції "Замовлення")
           └── OrderPreview (Макет форми замовлення)
                ├── FormField (Обгортка для полів вводу)
                └── AppButton (Кнопка підтвердження)

## 2. Контракти ключових компонентів (Props)

| Компонент | Вхідні властивості (Props) | Домовленість / Відповідальність |
| :--- | :--- | :--- |
| **AppLayout** | `title`, `links`, `children` | Створює спільну оболонку з шапкою, `main` та підвалом. `children` формує основний вміст. |
| **Section** | `id`, `title`, `children` | Забезпечує семантичний тег `<section>`, унікальний `id` для навігації та заголовок `<h2>`. |
| **BookList** | `books` | Масив об'єктів книг. Відповідає за мапінг масиву та обробку порожнього стану каталогу. |
| **BookCard** | `book` | Коректний об'єкт книги. Не залежить від джерела даних (локальний чи API), лише рендерить UI. |
| **AvailabilityBadge**| `available` | Логічне значення (`boolean`). Інкапсулює логіку вибору кольору та тексту для статусу. |
| **AppButton** | `type`, `variant`, `disabled`, `children` | Універсальна кнопка. `variant` (primary/secondary) визначає стилістику. |

## 3. Обґрунтування архітектурних рішень

1. **Використання композиції (children) у `Section` та `AppLayout`:**
   Замість того, щоб жорстко прописувати верстку кожної сторінки, створено компоненти-обгортки. `Section` відповідає лише за рамки, відступи та заголовок, дозволяючи передавати всередину будь-який вміст (список книг або форму). Це усунуло дублювання HTML-тегів.
2. **Виділення `AvailabilityBadge` в окремий UI-компонент:**
   Правило визначення статусу ("В наявності" чи "Очікується") та його стилізація винесені з `BookCard`. Це дозволить повторно використовувати цей бейдж на сторінці кошика без дублювання логіки перевірки наявності.
3. **Розділення `BookList` та `BookCard`:**
   `BookList` відповідає виключно за рендеринг списку (і відображення заглушки, якщо книг немає), а `BookCard` відповідає за відображення однієї одиниці. Це дотримується принципу єдиної відповідальності (Single Responsibility Principle).
