# Архітектура компонентів проєкту "BookStore"

Цей документ описує структуру клієнтського застосунку, розподіл відповідальності між компонентами, їхні контракти та керування станом (згідно з ЛР 1.2 та ЛР 2.1).

## 1. Ієрархія компонентів
Дерево відображає еволюцію вкладеності компонентів на поточному етапі розробки:

App (Точка входу, передає глобальні дані)
 └── AppLayout (Головна оболонка)
      ├── SiteHeader (Шапка)
      │    └── MainNav (Навігація)
      └── BookSelectionProvider (Context API: глобальний стан вибору книги)
           ├── HomePage (Сторінка каталогу)
           │    ├── Section (Обгортка секції "Каталог")
           │    ├── BookFilters (Керовані поля пошуку та фільтрації)
           │    └── BookList (Список книг)
           │         └── BookCard (Картка окремої книги + локальний стан)
           │              ├── AvailabilityBadge (Статус наявності)
           │              └── AppButton (Кнопки дій)
           └── OrderPage (Сторінка оформлення замовлення + стан чернетки)
                └── Section (Обгортка секції "Замовлення")
                     ├── OrderForm (Керована форма)
                     │    ├── FormField (Обгортка для полів вводу)
                     │    └── AppButton (Кнопки дій)
                     └── OrderSummary (Підсумок замовлення з обчисленою ціною)

## 2. Контракти ключових компонентів (Props)

| Компонент | Вхідні властивості (Props) | Домовленість / Відповідальність |
| :--- | :--- | :--- |
| **AppLayout** | `title`, `links`, `children` | Створює спільну оболонку з шапкою, `main` та підвалом. `children` формує основний вміст. |
| **Section** | `id`, `title`, `children` | Забезпечує семантичний тег `<section>`, унікальний `id` для навігації та заголовок `<h2>`. |
| **BookList** | `books`, `selectedId`, `onSelect` | Відповідає за мапінг масиву, обробку порожнього стану та прокидання колбеку вибору в картку. |
| **BookCard** | `book`, `selected`, `onSelect` | Не залежить від джерела даних (локальний чи API), рендерить UI та повідомляє про вибір книги. |
| **AvailabilityBadge**| `available` | Логічне значення (`boolean`). Інкапсулює логіку вибору кольору та тексту для статусу. |
| **AppButton** | `type`, `variant`, `disabled`, `children` | Універсальна кнопка. `variant` (primary/secondary) визначає стилістику. |
| **BookFilters** | `query`, `availableOnly` + callbacks | Відображає керовані поля вводу для пошуку. Завжди відображає передані значення стану. |
| **OrderForm** | `bookTitle`, `draft` + callbacks | Керована форма для збору даних клієнта (кількість, доставка, адреса). Без власного стану. |

## 3. Карта стану застосунку

| Значення / Стан | Призначення | Власник стану | Споживачі | Дія скидання |
| :--- | :--- | :--- | :--- | :--- |
| `detailsOpen` | Розгортання опису книги | `BookCard` (локальний) | `BookCard` | Демонтування картки |
| `query`, `availableOnly`| Фільтрація каталогу | Хук `useBookFilters` | `BookFilters`, `BookList` (через похідний масив) | Виклик `resetFilters` |
| `selectedId` | Вибір книги | `BookSelectionProvider` | `HomePage` (підсвітка), `OrderPage` (передача у форму) | Виклик `clearSelection` |
| `draft` (чернетка) | Дані вводу форми | `OrderPage` (спільний предок) | `OrderForm`, `OrderSummary` | Кнопка "Очистити поля", зміна книги |
| `visibleBooks` | Відфільтрований список | *Похідне значення* | `BookList` | Не застосовується |

## 4. Контракти подій (Callbacks)

Для забезпечення одностороннього потоку даних (Data Flow) дочірні компоненти повідомляють власників стану про дії користувача через callback-функції:
*   `onSelect(id)`: Відправник — `BookCard`. Власник — `BookSelectionProvider`. Змінює глобально обрану книгу.
*   `onQueryChange(text)`, `onAvailableChange(bool)`: Відправник — `BookFilters`. Власник — `useBookFilters`. Оновлюють параметри пошуку.
*   `onDraftChange(name, value)`: Відправник — `OrderForm`. Власник — `OrderPage`. Оновлює конкретне поле в об'єкті чернетки, зберігаючи інші поля незмінними.

## 5. Обґрунтування архітектурних рішень

1. **Використання композиції (children) у `Section` та `AppLayout`:**
   Замість того, щоб жорстко прописувати верстку кожної сторінки, створено компоненти-обгортки. `Section` відповідає лише за рамки, відступи та заголовок, дозволяючи передавати всередину будь-який вміст (список книг або форму). Це усунуло дублювання HTML-тегів.
2. **Виділення `AvailabilityBadge` в окремий UI-компонент:**
   Правило визначення статусу ("В наявності" чи "Очікується") та його стилізація винесені з `BookCard`. Це дозволить повторно використовувати цей бейдж на сторінці кошика без дублювання логіки перевірки наявності.
3. **Розділення `BookList` та `BookCard`:**
   `BookList` відповідає виключно за рендеринг списку (і відображення заглушки, якщо книг немає), а `BookCard` відповідає за відображення однієї одиниці. Це дотримується принципу єдиної відповідальності (Single Responsibility Principle).
4. **Context API для `selectedId` (Область провайдера):**
   Провайдер `BookSelectionProvider` обгортає лише основний вміст, не зачіпаючи `SiteHeader` та навігацію. Це дозволило усунути проблему надмірного прокидання пропсів (prop drilling) і синхронізувати каталог із сторінкою оформлення.
5. **Підняття стану для `draft`:**
   Стан уведених даних форми розміщено у `OrderPage`, а не всередині `OrderForm`. Це зроблено для того, щоб сусідній компонент `OrderSummary` міг отримувати актуальну кількість примірників та наявність доставки для динамічного перерахунку загальної вартості (Total Price).
6. **Інкапсуляція ефектів (useEffect):**
   Ефект синхронізації застосовано виключно для зміни зовнішнього API браузера (`document.title` при виборі книги). Він не використовується для фільтрації чи оновлення внутрішніх даних застосунку, щоб уникнути зайвих циклів рендерингу.
